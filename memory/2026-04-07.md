## 中午前：方案 A-v2 已实施并通过三判官闭环验收

- 这次没有直接拍脑袋改，而是走了一轮完整的**多 agent 闭环**：4 路调查（流程/状态机、写作方法论、风险/回归、验收标准）→ 3 路评审 → 独立实施 → 3 路判官验收。
- 三位评审的共同结论是：**方案 A 可以做，但只能做成“极轻适配层”**。不能长出第二个 orchestrator、第二 reviewer、第二 Humanizer，也不能把 khazix-writer 的壳子直接搬过来。
- 已正式落地 `XIAOLONGXIA_WRITER_LITE.md`，并把它定位写死为：**caller-side adapter + preflight gate**。作用只剩两件事：
  1. 定题后、Research 前生成 `writer-lite-brief.json`
  2. Writer 初稿后、Review 前跑一次 `writer-lite-check.json`
- 已同步修改 `AGENTS.md` 与 `MEMORY.md`：当前主流程新增 **“写前原型作战卡 + 写后（review 前）mechanical-only 预检”**。lite 明确只做有限机械检查，不打分、不替代 reviewer/fact-check，也不会再引入中间编排层。
- 这次最终收成的不是“大写作系统”，而是**作战卡 + 红灯预检**：
  - brief 只保留最小字段：`prototype / hot_hook / thesis / ai_punchline / must_keep / must_avoid`
  - preflight 只抓有限 hard fail，不做第二审稿
  - Reviewer 是 primary adjudicator；默认保持对长上游上下文的独立性，只有做一致性核对时才允许看最小必要 brief 摘要，且绝不把它当评分标准
- AI 边界也顺手写得更硬了：主 agent 是 brief 唯一批准者；Researcher 只有证据型纠偏建议权；Writer/Humanizer/Layout 无权改 brief；Humanizer 仍只是清 AI 味 + 顺节奏，不是第二 writer。
- durability 这次也补上了：`writer-lite-brief.json` / `writer-lite-check.json` 必须绑定 `draft_version`，至少带 `draft_version / updated_at / change_reason`；旧 check 在版本变化后自动过期。另放了 `out/writer-lite-demo/` 样例做最小可验产物。
- 后续控制面又补了一刀：若 `last_draft_file` 与 canonical `writer-lite-check.json` 的 `draft_version` / `draft_sha256` 不匹配，必须通过 `ensure_latest_lite_binding.py` **重跑 lite preflight**或**显式写 waiver**，并把结果落到 `writer-lite-binding.json` + `pipeline-state.json.lite_preflight`。
- 三位判官最终结果：**PASS / PASS / PASS**。结论一致：A-v2 已经落成一个可用的极轻适配层，没有滑成第二套写作管理系统。
- 仅剩一个非阻断尾巴：当前 demo 还是 simulated sample，还不是一次真实晚 8 点流程沉淀下来的现场 artifact；另外 sidecar 的固定落盘目录 / 命名规范还没进一步 canonicalize。先不扩 scope，后续真跑几轮后再看要不要收口。

## 下午前段：writer / review 重平衡 B1 已通过三判官闭环验收

- 老板中午追问了一个更第一性的问题：当前 writer 会不会因为背了太多预判和下游兼容压力而失去创造力？review 会不会因为过严，把文章磨得过死？随即我按 **full-closed-loop** 再开了一轮严肃闭环，不在原有 A-v2 上拍脑袋追加规则。
- 这轮 4 路调查的共同主线很清楚：**问题不是 lite 太重，也不是 Humanizer 夺权，而是“写作现场还混着审稿现场的空气”**。具体说：Writer 还在提前内化 reviewer / SEO / 下游改稿的心智负担；Reviewer 又把不少“传播优化偏好”混成了通过线。结果就是稿子更稳，但更容易写成“合格安全稿”。
- 基于 3 路评审（全部 `APPROVE_WITH_CONCERNS`），收口出 B1：不新增角色，不改发布控制面，不扩 Humanizer / Layout，只做 **caller-side 收口 + reviewer gate 小手术 + writer-prompt 极小错位清理**。
- B1 的核心变化：
  1. **Writer 重新定义回“方向内创作”**：在锁定的 `hook / thesis / ai_punchline` 内，先写出最有作者感、最能被复述的一版初稿。
  2. 新增 **“三保住”**：1 个可转述判断、1 个截图级段落、1 个具体情绪场景——但这三项被明确写成**创作目标，不是 blocker**。
  3. `writer-lite-brief` 被进一步收紧：**只能锁方向，不能锁成文方案**；锁角度边界，不锁段落设计；锁核心判断，不锁修辞路线；`must_keep` / `must_avoid` 默认各≤3。
  4. lite preflight 已收口为 **mechanical-only preflight**：具体范围只认 `writer_lite_preflight.py` 的脚本合同与生成 artifact，不在顶层规则里另写第二套语义红灯名单；它不提供风格建议，也不扩成第二 reviewer / 第二 fact-check。
  5. **Humanizer 明确不是救火队**：不补逻辑、不补事实、不改 thesis；真需要补这些，必须回退上游。
  6. reviewer-rubric 被正式改成 **`BLOCKERS` / `UPGRADE_SUGGESTIONS` 双层输出**：只有 `BLOCKERS` 能阻塞；`UPGRADE` 默认不阻塞，且默认最多 3 条。
  7. review 的 gate 语义被写死成：**先看有没有 blocker，再看分数**；分数继续保留，但不再拥有独立 veto 地位。旧的 `weighted_total` / 单项 <6 / `Originality >= 7` 不再自己决定 fail。
  8. 新增 **“保亮点义务”**：reviewer 必须指出最值得保住的一句判断 / 一处锋芒 / 一个截图段落或情绪场景；但也明确写死：**亮点不能给 blocker 赎罪**。
- 这轮 3 位判官最终结果：**PASS / PASS / PASS**。一致结论：B1 已经不是“换个说法继续过审”，而是形成了一个**可执行的重平衡**——writer 确实减压，review 确实回到 blocker-first，三保住也没有膨胀成新 checklist。
- 仍需长期盯住的 4 个“回胖风险”也一并记下：
  1. lite 现在口头上会被总结成“三红灯”，但细则里仍有 6 类 hard fail，后续若继续加条目，容易回胖；
  2. writer-prompt 里仍保留较强自检负担，执行文化一重，writer 可能重新脑内过审；
  3. reviewer-rubric 完整分表仍在，如果操作者文化继续盯总分，旧强控可能回潮；
  4. 若 brief 再次写满，lite 中的方向性 hard fail 仍可能把 writer 压回“按正确答案写稿”。
