## HEARTBEAT 误判补充

- 今天 10:03–10:21 出现的 **3 分钟一轮密集 HEARTBEAT 汇报**，不是 `openclaw.json` 当前 heartbeat 配置导致的。
- 已核实：当前生效 heartbeat 仍是 **30m**（全局 30m，xiaolongxia 自身 30m；`openclaw status` 也显示 30m）。
- 那波密集汇报的真实触发源是：**主会话反复收到“Read HEARTBEAT.md ...”这类注入式 heartbeat 指令**；对外可见发送者仍是主 agent 本身。
- 结论：
  - **发送层：主 agent**
  - **触发层：重复 HEARTBEAT 指令注入 / 投喂**
  - **不是 subagent 嵌套链路导致**
  - **不是当前 heartbeat=30m 配置本身导致**
- 这次教训：以后 heartbeat 汇报必须严格区分“当前实际生效配置”与“当前会话收到的重复触发消息”，不能把历史临时状态或外部重复注入误说成配置值本身。
