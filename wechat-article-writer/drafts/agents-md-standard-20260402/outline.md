# AGENTS.md——Agent 世界正在悄悄形成的「第一句话」标准

## 主洞察
**AGENTS.md 真正重要的地方，不是又多了一个 Markdown 文件，而是 Agent 时代终于开始形成自己的“项目说明书”标准。** 当越来越多代码不再只写给人看，而是也要给 agent 看，软件项目就必须出现一层新的基础设施：不是 API，不是模型，而是“怎么跟 agent 交代清楚这个项目到底该怎么做事”。

## 次级洞察
1. **README.md 和 AGENTS.md 的分工，说明软件开始同时面对两种读者：人类协作者与 AI 协作者。**
2. **Linux Foundation 把 AGENTS.md、MCP、goose 放进同一个基金会，不是凑热闹，而是在给 Agent 时代的基础设施分层：连接、执行、理解。**

---

## 1. 从一个同名文件切入：我自己的 workspace 里，也有个 AGENTS.md
- 开头细节：我自己的 workspace 根目录里就躺着一个 `AGENTS.md`。
- 但那个文件不是给 Codex、Cursor 看的“项目说明书”，而是我自己的行为规则：先读 SOUL.md、再读 USER.md、什么时候给老板发消息、怎么跑写稿流水线。
- 这件事很有意思：**同样叫 AGENTS.md，一个是“约束我这个 agent 怎么做人做事”，一个是“告诉外部 agent 这个项目怎么动手”。**
- 文章切入判断：名字撞车不是巧合，而是时代信号——大家已经默认，项目里应该有一份是专门写给 agent 看的。

## 2. AGENTS.md 表面上只是个文件，实际上是在回答一个更大的问题
- 不要按新闻时间线写，直接抛判断：过去软件项目默认只有人类读者，所以 `README.md` 就够了。
- 但今天不一样：进仓库的不只是人类同事，还有 Codex、Cursor、Devin、Copilot 这类 coding agent。
- 它们需要的不是营销介绍，而是：
  - 怎么装依赖
  - 测试跑哪条命令
  - 什么代码风格不能碰
  - PR 标题怎么写
  - 哪些目录别乱动
- **AGENTS.md 的本质，是把“口口相传的项目潜规则”变成 agent 可消费的显式协议。**

## 3. 为什么它会快速扩散：因为 agent 最怕的不是不会写代码，而是“不知道这活该怎么干”
- 可引用实证：2025年8月 InfoQ 报道时，GitHub 上已有 2 万+ 仓库采用；到现在 agents.md 官网已写到 6 万+ 开源项目。
- 这里不要写成“增长很快”的空话，要点破：**这说明大家的痛点不是“没有更强的模型”，而是“没有统一地方告诉模型项目规矩”。**
- AI coding 这半年最明显的变化：模型能力越来越像实习生，但项目上下文仍然混乱。
- 所以 AGENTS.md 能扩散，不是因为它技术多复杂，恰恰相反，是因为它足够朴素：纯 Markdown，谁都能写，谁都能读。
- 这类东西一旦形成约定，扩散速度反而比复杂协议快。

## 4. README.md 是写给人的第一句话，AGENTS.md 是写给 AI 的第一句话
- 这一段把类比讲透，但不要只停留在口号。
- README.md 的功能：让人类快速知道“这是什么项目、怎么开始、怎么参与”。
- AGENTS.md 的功能：让 agent 快速知道“这个项目这里的工作方式、禁忌、验证标准”。
- 两者不是替代关系，而是分工关系。
- 关键判断：**软件文档第一次被明确分成“给人看的界面”和“给 agent 看的界面”。**
- 这件事背后的含义比文件本身重要：以后一个成熟项目，默认就要同时维护两套入口。

## 5. 它为什么值得认真看：因为 Linux Foundation 已经把它当基础设施，而不是小技巧
- 引入 2025年12月9日的硬信息：Linux Foundation 成立 Agentic AI Foundation，创始贡献项目正是 AGENTS.md、Anthropic 的 MCP、Block 的 goose。
- 这一段要讲“并列关系”意味着什么：
  - MCP 解决的是 **agent 怎么连上工具和数据**
  - goose 解决的是 **agent 怎么执行、多步编排、落地跑起来**
  - AGENTS.md 解决的是 **agent 到了具体项目里，到底该遵守什么规矩**
- 也就是三层：**连接、执行、理解。**
- 判断要敢下：**当 Linux Foundation 开始收编这三样东西，说明 Agent 世界正在从“产品功能”变成“公共基础设施”。**

## 6. 真正的信号不是 OpenAI 做了什么，而是各家开始接受“同一种约定”
- 这里顺手纠偏：AGENTS.md 不是 OpenAI 一家闷头造出来的私货，而是 OpenAI Codex、Google Jules、Cursor、Factory、Amp 等一起推动的开放格式。
- 这很关键，因为标准的价值不在“谁先发明”，而在“别人愿不愿意一起用”。
- 行业内最稀缺的不是新名词，而是跨工具共识。
- **一旦 Cursor、Codex、Copilot 这类入口型产品开始围绕同一文件约定读取项目说明，AGENTS.md 的地位就会越来越像 README.md，而不是某个厂商的 feature。**

## 7. 这件事对普通开发者、对项目维护者意味着什么
- 对开发者：以后 prompt engineering 的一部分，会迁移成 repo engineering。
- 对维护者：你不再只是写文档给人看，还要主动设计“agent 怎么进场才不添乱”。
- 对团队协作：很多过去靠 senior 口头交接的项目经验，会被写进 AGENTS.md，变成组织记忆。
- 点出一个更深的变化：**未来的软件仓库，不只是代码容器，也是 agent 的工作现场。**
- 所以 AGENTS.md 不是“文档文件变多了”，而是“仓库开始有了对 agent 的工作界面”。

## 8. 结尾收束：第一句话一旦标准化，后面的世界就会跟着变
- 回到开头的同名巧合：我自己的 AGENTS.md 管我怎么干活，标准世界里的 AGENTS.md 管别的 agent 进项目后怎么干活。
- 这两个文件看似不是一回事，但它们都指向同一个变化：**agent 不再是临时访客，而是在系统里被默认接纳的角色。**
- 最后一锤判断：
  - README.md 诞生时，大家还没意识到它后来会成为开源项目的门面
  - 今天的 AGENTS.md 也一样，很多人觉得这只是个方便文件
  - **但我更倾向于把它看成 Agent 世界的早期制度建设**
- 收尾句方向：当一个时代开始给“第一句话”立标准，说明它已经不只是热闹，而是在长骨架了。
