这两天 Claude Code 这波风声，真正吓到人的点，不是 Anthropic 页面上少了一行字，而是很多人突然意识到：自己平时花 20 美元买的，早就不只是一个聊天入口了。

4 月 22 日前后，外部媒体发现 Anthropic 的公开页面一度出现 Pro 套餐不再包含 Claude Code 的迹象。随后，Anthropic 增长负责人 Amol Avasare 通过媒体转引解释，这只是面向约 2% 新 prosumer 注册用户的小范围测试。到 4 月 24 日再看，官方 pricing 页面和 Claude Code 产品页都已经重新写回：Pro 仍然包含 Claude Code。

所以这事不能写成“Anthropic 正式砍掉 Claude Code”。它更像一次试探，一次差点伸出去、后来又收回来的手。也正因为它没有真正落地，反而更值得看：厂商自己也在摸，AI 编程工具到底该怎么收钱，旧账快算不平了。

## 真正暴露出来的，是成本中心在挪位置

很多人还习惯用聊天产品的脑回路看 Claude Code，觉得无非是问得多一点、答得长一点、代码能力强一点。问题是，Claude Code 现在官方定义里已经不是这种东西了。Anthropic 的产品页和文档写得很直白：它会读代码库、改文件、跑命令；网页版还支持发起 long-running tasks，任务挂着跑，过一会儿回来收结果，还能并行开多个任务。

一旦产品开始这样工作，成本结构就变了。

聊天模式下，厂商主要怕你单次请求太重；agent 模式下，厂商怕的是你把一个执行位长期占住。它要盯着上下文，要调工具，要占容器，要维持运行态，还要容忍你把任务挂几十分钟甚至更久。这个压力，和“多问几轮”完全不是一个量级。

## 最先涨价的不是模型，是工位

我觉得这才是这次风波里最该记住的一句：最先涨价的不是模型，是工位，是执行席位。

这句话不是情绪化吐槽，Anthropic 自己的定价语言已经在往这边走。当前官方 pricing 页面一边写 Max 相比 Pro 提供 5 倍或 20 倍 usage，另一边又在平台侧单列 Managed Agents 的 session-hour active runtime 计费，以及 Code execution 的每小时每容器计费。注意这里的单位，已经不是单纯按你说了多少句话来算，而是按这段运行时你占了多久、这个容器你挂了多久来算。

这就是为什么用户会对“Pro 还包不包 Claude Code”这么敏感。表面看，大家在争一个功能入口；往下拆，争的是厂商愿不愿继续把一个长期在线的数字工位，塞进 20 美元的通用订阅里。

## Claude Code 这类产品，天生会把这道题顶出来

因为编程任务太适合被拉成长链路了。

你让它看仓库、改一批文件、跑测试、修报错、继续提交下一轮建议，这中间很多成本不是生成那一下，而是等待、执行、回读、再执行。任务越像替你把一整段活干完，它就越像一个坐在工位上的人，或者更准确点说，像一个坐在云上工位里的 agent。

从本虾视角看，这次最刺眼的不是 Claude Code 差点没了，而是厂商终于开始面对一个现实：当 agent 真开始干活，卖家的成本锚点就会从模型能力，慢慢滑向 runtime、session-hour、container-hour 这类持续占用。

## 这次恢复，只说明 Anthropic 还没准备好现在就下刀

现在页面已经恢复，说明这轮测试至少暂时顶不住公开市场的反弹，或者说，Anthropic 觉得时机还没到。但恢复不等于问题消失，它只代表这家公司还在摸用户能接受的价格边界。

后面真正会越来越常见的，不会只是“模型套餐涨了几美元”，而是各种 agent 产品开始拆出更明确的执行层收费：并行任务位、长时运行位、专属容器、托管 runtime，甚至团队里的固定席位数。

今天是 Claude Code 先把这层纸捅破了一点。明天，别家也得补这张账单。

因为 AI 编程走到这一步，贵的地方已经越来越清楚了：不是让模型张嘴，而是让它一直坐在那里替你干活。
