browser-use、Agent、OpenClaw browser，为什么网页任务要分成单步 CLI、多步 Agent

今天这篇我想先把结论摊开讲。

很多人以为，网页任务无非就是点网页。可真把 Agent 放进生产环境里，你很快就会发现，真正拉开差距的东西，跟模型会不会聊天关系没那么大，跟网页活有没有分流，关系特别大。

同样是浏览器里的动作，有些活适合一条命令直达，有些活天生要边看边走。分错了，速度会掉，稳定性会掉，排障时你会被整得头皮发麻。分对了，整个系统一下就顺了。

这才是今天这次翻车最值钱的地方。

先把脑图立住。

browser-use CLI，适合路线很直的网页动作。你已经知道去哪、点什么、拿什么结果，比如打开 example.com，截一张图，结束。

Browser Use Agent，适合那种走着走着还得自己认路的活。页面会变，按钮会换位置，点进去以后还要判断下一步，这种任务更像把一个会动手的助理放进浏览器里。

OpenClaw browser，则是另一条浏览器能力线，也能控制网页，也能做交互。只是在小龙虾今天这条工作流里，它当前不是默认主路线。主力执行落在 browser-use 这条线上，里面再分 CLI 和 Agent 两种工作方式。

你把这三层关系想明白，后面很多问题就顺了。

模型负责判断，执行器负责动手，系统负责分流。

这句话看着像架构黑话，其实跟日常协作很像。脑子负责决定去哪，手脚负责把门推开，调度的人负责安排谁先上。网页执行正在长成独立专业执行层，说的就是这件事。

事情是怎么暴露出来的。

一开始，我们跑的是很简单的网页动作，打开页面，截图，拿结果回来。这种活很利落，CLI 一把就过了。说真的，这种场景你硬把 Agent 叫出来，反而像让一个很能干的人专门下楼拿快递，当然也能拿，成本有点高。

可任务一旦变成另一种画风，难度立刻抬起来了。

你不只是让它打开网页，你还让它自己看页面，找入口，点进去，再继续判断往哪走。今天这条多步路线，从 example.com 到 Learn more，最后落到 IANA 的 Example Domains 页面，英文和中文任务都跑通了。这个结果很关键，它证明网页任务已经天然分层。

单步任务，CLI 更快。

多步任务，Agent 更稳。

普通读者为什么要关心这个判断。

因为它直接决定你以后用 Agent 的体感。你是会觉得这玩意真能干活，还是会觉得它磨磨唧唧、动不动卡死、出了事根本查不清。很多时候，差别就出在这里。

今天真正让我上头的，是中途那次卡死特别有代表性。

下午任务一度卡在 watchdog，页面像被按了暂停键，新的浏览器会话起不来，Agent 也推进不下去。盯着终端看了几分钟，系统像一群人站在门口互相等，谁都不往前走。那种感觉特别具体，你明明知道司机会开车，车也停在路边，钥匙却被另一个人揣在兜里，谁都走不了。

后来把问题掰开看，根因并不神秘。

同一份浏览器身份，被两个执行动作同时盯上了。

你可以把 profile 理解成浏览器的那套个人状态，里面有登录信息、历史痕迹、现场上下文。今天已经有一个 default Chromium 占着这套状态了，系统又想临时再拉一个本地会话进来，用同一把钥匙开同一扇门。于是就抢起来了。抢到最后，watchdog 也跟着僵住。

这时候再提术语就好懂多了。

profile 并发占用，说的就是多人同时抢一个浏览器身份。

CDP 复用，说的是现场已经有个能干活的浏览器会话在跑，就别再重新拉一套班子，直接接管它、复用它。

后面的修复动作，其实很像成熟团队会做的选择。我们没有继续硬起第二个实例，而是优先复用已经跑着的 default 会话 CDP。路子一换，多步 Agent 很快恢复成功。

这一下给我的感觉很强烈。

很多人还在讨论模型聪不聪明，网页执行这一层已经开始卷专业分工了。前台你看到的是一个会做事的浏览器助理，后台接哪条模型通道，哪条浏览器路线，哪个现成会话能接手，其实是另一层系统协作。今天 Browser Use Agent 侧露出的 openclaw/xiaolongxia，这种信号就很明显。

对普通用户来说，你未必要记住 watchdog、profile、CDP 这些词。

你只要记住一个判断就够了。

打开网页、点一个确定按钮、截一张图，这类路线清楚的活，交给 CLI，省时间，也省排障成本。需要自己认页面、连续推进、随时判断下一步的活，交给 Agent，成功率更高，也更接近你想要的那个数字助理。

这背后并不只是工具分工，它会反过来改写大家理解 Agent 的方式。

以前很多人觉得，模型够强，网页执行自然会跟着变强。现在看，事情已经往另一边走了。模型当然重要，可真正把网页任务做顺的，越来越依赖执行器能不能稳定动手，系统能不能把对的活交给对的路线。

这才是我今天最想落下来的判断。

网页执行，正在从模型身上的附带技能，长成一层独立的专业执行层。

以后谁的 Agent 更像一个真能上班的数字员工，拼的也不会只是脑子快不快，更多会落在这套分流顺不顺。单步走 CLI，多步走 Agent，系统再把会话和资源安排明白。

谁先把这套东西捋顺，谁的网页助手，才真的能干活。
