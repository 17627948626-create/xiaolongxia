# 为什么现在做网页任务，要分成单步 CLI 与多步 Agent

## 以前我们总觉得，网页任务就是点一点
- 在普通人眼里，打开网页、点个按钮、截图发回来，看上去都属于同一类活。
- 真正上手后才会发现，网页动作外表相似，难度却差得很远。
- 有的任务路线很直，像把门推开、把画面截下来，动作短，目标清楚。
- 有的任务像让人进一个陌生商场，先找电梯，再找楼层，再看指示牌，过程中还得边走边判断。
- 这就是今天这篇文章想讲透的东西，网页执行已经开始分层了。

## 一个会点网页的模型，和一个会跑流程的执行层，不是一回事
- 过去大家习惯把网页执行也算进大模型的能力清单里，仿佛模型只要够强，顺手就能把网页活一起做了。
- 现在更接近现实的理解，是网页执行正在长出自己的专业角色。
- 模型负责理解目标、做判断、决定往哪走。
- 浏览器执行器负责真正进网页、接页面、拿状态、推进动作。
- 这套关系很像项目经理和执行员，一个负责判断路线，一个负责把动作稳稳落地。

## 为什么单步任务更适合 CLI
- 有些网页任务非常确定，打开这个网址，截一张图，保存一个结果，动作清晰，路径固定。
- 这类任务最怕绕远路，给它一条明确命令，执行往往又快又稳。
- 今天已经实测通过，CLI 路线可以顺利打开 example.com，也能成功截图。
- 这说明当任务没有分支、没有判断、没有临场导航需求时，命令式执行反而最省。
- 用车来打比方，这更像手动挡，路线已经知道了，直接挂挡往前走就行。

## 为什么多步任务更适合 Browser Use Agent
- 另一类网页任务不只是在点一个按钮，它要求系统自己看页面、找入口、处理跳转、判断下一步。
- 这样的任务一旦交给纯命令式执行，就会很快遇到页面变化、元素位置不稳定、流程分支不固定的问题。
- Browser Use Agent 的价值，就在于它能把多步、自主导航、边看边做的活接过去。
- 今天也已经实测通过，多步任务可以从 example.com 出发，点击 Learn more，再落到 IANA 的 Example Domains 页面。
- 这类执行更像自动挡，或者像一个有脑子的浏览器助理，目标给它，它来负责在页面里找路。

## 真正拖慢任务的，很多时候是执行层怎么协作
- 今天最有信息量的地方，并不只是任务跑通了，而是中间那次卡顿暴露了系统真实的脆点。
- 一开始 Agent 路线连续卡在 watchdog，看上去像模型没干活，实际问题出在浏览器 profile 被抢占。
- 同一个 user_data_dir 已经被现成 default Chromium 占着时，再起一个本地 BrowserSession，就像两个人同时去抢同一把钥匙，最后谁都走不顺。
- 这个故障很值得写，因为它让读者看见，网页任务做不好，未必是模型不会想，也可能是执行层在互相打架。
- 当系统进入网页时代，资源协调本身就成了能力的一部分。

## 修复为什么能说明‘浏览器执行层’正在成熟
- 后面的修复没有继续硬起第二个本地浏览器实例，而是改成优先复用已有 default 会话的 CDP。
- 这个动作听上去像技术细节，实际特别像成熟团队会做的事，先看现场有没有已经能用的执行资源，再决定怎么接力。
- 一旦会话复用起来，多步 Agent 任务就恢复成功了。
- 这说明网页执行层真正需要的，已经不只是一个会思考的模型，还包括会不会复用上下文、会不会避开冲突、会不会把动作接在已有会话上。
- 说得更直白一点，系统开始学会合作了。

## OpenClaw browser 的位置，也要讲清楚
- 这套讨论里还有一个容易混淆的点，就是 OpenClaw browser。
- 它也是一套浏览器工具，也能做网页控制。
- 但在小龙虾这条已经对齐的工作流里，它当前不是默认主路线。
- 这个位置讲清，读者才能理解为什么同样都叫浏览器能力，最后却会落到不同执行层上。
- 文章里可以把它写成平行工具线，而不是主舞台中央的角色。

## 为什么 Browser Use Agent 侧会写 openclaw/xiaolongxia
- 这件事不需要写成配置教程，但很值得当作一个认知点提一下。
- Browser Use Agent 侧模型名写 openclaw/xiaolongxia，背后透露的是架构分层已经存在。
- 对普通读者来说，可以理解成你眼前看到的是会干活的浏览器助理，背后接哪条模型通道，是另一层系统安排。
- 当一套系统开始把前台执行与后台模型入口拆开，它通常意味着工作流已经从玩具状态往工程状态走了。

## 以后网页任务真正拼的，会是分流能力
- 今天的结论很适合收成一句普通人也能复述的话，网页执行以后拼的，不只是模型聪不聪明，还包括系统会不会把不同难度的活交给对的人。
- 打开页面、截图、保存这类确定性动作，交给 CLI，省力也省时。
- 进站、找入口、判断分支、连续推进这类任务，交给 Agent，成功率更高。
- 这背后的大方向很清楚，网页执行正在从模型附属能力，变成一层独立的专业执行层。
- 谁更早把这套分工跑顺，谁的 Agent 才更像真正能上班的数字员工。

## 最后，为什么这件事值得普通读者现在就看懂
- 很多人以为网页自动化只是在比模型能不能点到那个按钮。
- 现实已经往前走了一步，问题变成了谁来点、怎么点、在什么场景下点，整套执行链路要怎么接。
- 今天这轮实测给出的答案很朴素，也很重要，网页世界里的 AI 正在学会像团队一样分工。
- 当单步 CLI 和多步 Agent 各归各位，浏览器执行这件事才会真正开始变稳。
- 这可能才是下一阶段 Agent 走进真实网页环境时，最容易被低估的一层基础设施。
